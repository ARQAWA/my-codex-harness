# Filesystem Search — дизайн и история

Дизайн-файл плагина `filesystem-search`. Описывает только этот плагин и его
необходимые внешние контракты. Общие правила репозитория — в `AGENTS.md`.

## Текущий контракт: отдельные маршруты по ОС

На macOS/Linux сохраняются действующие маршруты и установка: известный точный
путь читается напрямую; Codebase Memory (CBM) MCP отвечает за код, символы,
вызовы, зависимости и отношения; `tgrep` MCP — за текст, имена, документацию
и конфигурацию; `ast-grep` MCP применяется, когда indexed results не отвечают
на структурный вопрос синтаксиса. Индексы
CBM и `tgrep` находятся в пользовательских кэшах, а `ast-grep` не создаёт
постоянный текстовый индекс.

На native Windows 11 точный известный путь также читается напрямую, текст
ищется командой `rg -n`, а имена файлов — `rg --files`. Для кода и отношений
используется отдельный внешний CBM MCP, для синтаксиса — отдельный внешний
`ast-grep` MCP. Windows-установка описана отдельно от macOS/Linux в
`install-instructions/filesystem-search-windows.md`; она не устанавливает и не
использует `tgrep`.

На Windows `auto_index = true` настраивается в пользовательской конфигурации
самого CBM. Обычный поиск не требует предварительного `index_repository`; если
его вызывают явно, передают `persistence: false`. Граф CBM хранится в
пользовательском кэше, плагин не создаёт `.codebase-memory/graph.db.zst` в
проекте, а `ast-grep` не требует постоянного текстового индекса. CBM и
`ast-grep` — процессы, отдельно регистрируемые Codex-инсталляцией пользователя;
manifest и plugin hooks их не запускают.

Для обеих ОС свежие, отрицательные и требующие полного охвата выводы
сверяются с текущими файлами и фактическими границами поиска; hidden и ignored
пути учитываются, когда это существенно. Неполный или устаревший CBM граф не
считается доказательством отсутствия связи. Если конкретный MCP отсутствует,
не прошёл handshake или его вызов не удался, недоступность этой функции
называется прямо. `rg` и чтение исходников используются лишь для тех вопросов,
на которые они отвечают; их совпадения не выдаются за графовые связи или AST.
CBM может индексировать каталог без Git, но его native watcher там не
обновляет граф автоматически; для свежести в таком каталоге проверяются
текущие файлы.

Плагин сохраняет два context hook. `SessionStart` и `SubagentStart` выбирают
короткий маршрут по `process.platform` и только передают его через stdout.
Они не ищут и не индексируют файлы, не запускают процессы или MCP и не
блокируют инструменты. У плагина нет собственного daemon, watcher, wrapper,
проектного индекса или запуска MCP.

### Решение о платформенном разделении

Пользователь подтвердил, что текущие macOS/Linux-механика и установка уже
работают и должны остаться прежними; отдельный Windows-маршрут нужен из-за
наблюдавшегося отказа native Windows. Поэтому `tgrep` сохранён для macOS/Linux,
а Windows использует `rg` для текста и имён плюс те же внешние классы MCP для
графа и синтаксиса. Успешные вызовы Windows-серверов из отчёта были раздельными;
повторный сбой initialize CBM означает, что одновременная или постоянная
безотказность не гарантирована. Настройки grace/timeout и конкретная причина
сбоя остаются условиями проверенной VDI, а не общим обещанием дизайна.

Прежние единая инструкция установки и общий для всех ОС маршрут относятся к
истории решений и заменены разделением по платформам. Точные правила удаления
старой Windows-настройки даны в её установочной инструкции.

## Исторический контракт: штатные MCP до разделения по ОС

Ранее общий маршрут применял CBM для кода, `tgrep` для текста и файлов и
`ast-grep` для синтаксиса. Он также предполагал одну схему установки на всех
платформах. Это исторический контракт, заменённый решением выше: он не задаёт
Windows-маршрут или Windows-установку.

Прежнее решение не добавлять plugin hooks заменено решением добавить два
context hook для основного агента и субагентов. Hooks плагина не включают
отдельный hook или раздел `AGENTS.md` установщика `tgrep`.

## Исторический контракт: обёртки и Rust watcher

Следующее описание относится к ранее принятому, затем заменённому дизайну.
Оно не задаёт текущий runtime или порядок установки.

Цель — ускорить локальный поиск через поддерживаемые индексы. CBM основной
для кода и связей; tgrep вспомогательный для текста и путей, доступен напрямую
без предварительного CBM. AST — scoped fallback. Строгая свежесть текста
использует direct read/rg; отсутствие в графе не означает отсутствие файла.

Root берётся из session cwd в PreToolUse и передаётся через
`FSSEARCH_SESSION_ROOT`. Изменённый shell cwd его не заменяет. Обёртки
проверяют root, scopes и входные файлы, запрещают выход через ссылки и follow.
Hook охватывает shell/Bash; это защита от случайных вызовов, не sandbox.

Обёртки ждут отсутствующий индекс; готовый используют с допустимым фоновым
отставанием. Для CBM поставляется собственный Rust watcher, вызывающий штатный
CLI. Он рекурсивно наблюдает canonical project root через filesystem events,
независимо от Git, объединяя изменения за 5 секунд. Сам индексатор и выбор
incremental/full остаются в CBM; он применяет `.gitignore`, `.cbmignore` и
свои стандартные исключения, также для non-Git roots.
Индексы центральные;
удаление корня останавливает watcher, но не удаляет граф. CLI search wrapper
сам определяет project; агент больше не хранит dirty/identity состояние.

Один процесс CBM владеет root через SQLite exclusive transaction: OS освобождает
её при падении, а конкурентный запуск не может удалить socket живого владельца.
Это не новый индекс: база используется только как межпроцессная блокировка.
IPC — Unix socket в /tmp или Windows named pipe. Rust watcher упакован для
Ubuntu x86-64, macOS ARM64 и Windows x86-64; Node обёртки запускают
соответствующий установленный бинарник.

Tgrep сохраняет штатный serve и serve.lock. Индекс соблюдает штатные ignore
правила tgrep, включая `.gitignore` вне Git-репозитория
(`--no-require-git`) и `.ignore`; wrapper не включает `--no-ignore` при
построении корпуса и исключает `.git` через `--exclude`.
Hidden paths исключены из обычного поиска; явный `--hidden`
сохраняет обычные ignore-правила, а `.git` остаётся исключённым.
Положительные glob сохраняют индексный маршрут.
Сохраняются штатные ограничения типов/размера. Явный `--no-ignore`
переключается на совместимый rg-маршрут и не меняет обычный индексный корпус.
Нет секундного cutoff первого индекса. Смена политики корпуса требует одного
native rebuild после подтверждённой остановки старого serve; marker хранит
политику/root/PID. Lifecycle-блокировка сериализует обёртки; serve.lock остаётся
штатным владельцем самого сервера и не удаляется.

### Основание изменений

Пользователь уточнил исходную идею: CBM основной, tgrep вспомогательный, AST
fallback; демоны поддерживают индексы, небольшая временная неконсистентность
допустима. Затем разрешил Node CLI watcher CBM по алгоритму MCP watcher.
Позднее запросил перенос watcher на Rust и три packaged сборки для Linux,
macOS ARM64 и Windows VDI; этот контракт заменяет Node реализацию.
Исходники CBM 0.11.0 показали: one-shot CLI не поднимает штатный MCP daemon;
watcher.c можно повторить без переноса MCP. Прежнее Git-проверяемое
обслуживание было заменено root filesystem watcher: проект может не быть Git
репозиторием, а служебные git-метаданные не задают корпус поиска.

Прежние утверждения об отсутствии cwd в hook и автоматическом запуске daemon
через CBM CLI оказались неверны. Ниже они сохранены как история решений,
не как текущие инструкции. Реализация в исходниках не означает установку или
релиз; версия меняется только по отдельной release-процедуре.

## Более ранний исторический контракт

Обязательная маршрутизация discovery: tgrep для обычного текста, direct read
или rg для strict-current, ast-grep для синтаксиса, Codebase Memory CLI для
связей. Skill — единственная точка маршрутизации; выбирается один достаточный
backend.

Единая root-дисциплина для всех scoped-инструментов:

- Root каждого wrapper обязан равняться `canon(process.cwd())` — каталогу
  запуска текущей сессии, а не git-корню; проекты без git — штатный случай.
- Denylist: `os.homedir()`, `<codex-home>`, корень ФС. Нарушение — exit `2`.
- Scope — только существующие root-relative пути; `.` — осознанный
  project-wide запрос.
- Root-правило живёт только в wrappers (`scripts/root-guard.cjs` — один
  источник правды для всех wrappers). PreToolUse payload не содержит `cwd`,
  поэтому hook root не проверяет.
- Guard hook (`hooks/fssearch-guard.cjs`, matcher `^shell$`) работает по
  executable-токенам без парсинга путей и гонит рискованные операции через
  wrappers: прямой `tgrep serve/index`, CBM `index_repository` / `allow-root` /
  install-команды / bare server, прямой `ast-grep`/`sg` кроме help/version —
  deny. Read-only вызовы (CBM `cli` без index, `config`, help/version) —
  allow без вывода.

Индексы не живут в проектах:

- tgrep: `<codex-home>/tgrep/index/<sha1(realRoot).slice(0,12)>` — чистый hex,
  Windows-safe по построению; привязка индекс→проект читается из `meta.json`.
- CBM: собственное центральное хранилище `~/.cache/codebase-memory-mcp/`
  (hardcoded в CLI; `.codebase-memory/` внутри проекта не создаётся без
  `--persistence`).
- ast-grep и rg stateless — индекса нет.

### Прежние принятые решения

- Wrapper-only вход для ast-grep: каждый реальный вызов — потенциальный обход
  дерева, дешёвого read-only режима нет; поэтому hook блокирует прямой вызов
  целиком, а wrapper добавляет root-гарантию.
- Для CBM read-only CLI разрешён напрямую: без индексации эти вызовы не
  создают состояния и не обходят деревья. Тяжёлая операция — только
  `index_repository`, она закрыта wrapper `cbm-index.cjs` с фиксированным
  `--mode full`.
- Допустимые постоянные процессы — официальный `tgrep serve` и официальный
  CBM daemon (`--cbm-daemon-internal`, watcher по indexed-проектам,
  `auto_index=false` по умолчанию). Это штатный runtime инструментов, а не
  сторонние супервизоры.
- Общий `scripts/root-guard.cjs` для трёх wrappers: гарантирует идентичную
  дисциплину вместо копий.

### Прежние отклонённые решения

- Парсинг путей/cwd в hook: payload без `cwd`; любой путь-парсинг в hook —
  дыры и ложные срабатывания. Root-правило остаётся в wrappers.
- Перемещение хранилища CBM в `<codex-home>`: расположение `~/.cache`
  hardcoded в CBM CLI, настройки `data_dir` нет. Централизация уже есть;
  достаточно root-дискиплины.
- Отключение или замена официального CBM daemon: «Runtime не перепроектируй».
- Полный запрет прямого `rg`/strict-current чтения: strict-current текст —
  заказанный маршрут вне индексов.

## История

- 2026-09: исходный wrapper tgrep с грамматикой опций, rg-роутингом и
  lifecycle; per-repo индекс `<root>/.tgrep`.
- 2026-09-24 (инцидент): агент проиндексировал `$HOME` (5 ГБ, ~15 часов CPU)
  и `~/.codex` через tgrep. Принято: центральный индекс
  `<codex-home>/tgrep/index/<hash>`, root = canonical session cwd + denylist,
  guard hook против прямого `tgrep serve/index`, удаление per-repo `.tgrep`.
- 2026-09-24: распространение той же дисциплины на все инструменты плагина.
  Факты исследования: CBM CLI принимает любой `--repo-path` (встроенно
  блокирует только home и корень тома), хранит графы центрально в
  `~/.cache/codebase-memory-mcp/`, порождает официальный daemon; ast-grep
  stateless и принимает любые пути. Принято: общий `root-guard.cjs`, wrappers
  `ast-grep-search.cjs` и `cbm-index.cjs`, allowlist-модель hook, честная
  фиксация CBM daemon в документации вместо прежнего «нет permanent watcher».
