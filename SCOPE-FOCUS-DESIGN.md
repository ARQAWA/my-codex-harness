# Scope Focus: концепция и решения

Действующая концепция плагина. Прежние версии и отменённые решения доступны в
истории Git/GitHub и здесь не хранятся. Рабочих TODO и чек-листов релиза здесь
нет. Общие правила репозитория — `AGENTS.md`, установка — `install-instructions/`.

## Назначение

Scope Focus помогает Codex точно выполнять заказ без лишней работы. Согласованное
делается полностью, несогласованное не добавляется. Скорость измеряется временем
до правильного результата, а не числом ходов: независимые вызовы идут параллельно,
лишние чтения и проверки без нового входа не делаются.

Пользовательская часть синхронизируется с my-pi. Источники переноса:

| Часть | Источник в my-pi |
|---|---|
| системный промпт | `extensions/RQW-prompt/SYSTEM.md` |
| блок Communication в конце промпта | `extensions/RQW-dyslexia` |
| роль и цикл review | `extensions/RQW-review` |
| приёмы чтения и поиска | `extensions/RQW-tools` |

Переносится только то, что получает пользователь my-pi. Координатор,
`coordinator.lock`, `PROCESS.md`, `DECISIONS.md`, матрица моделей исполнителей,
профили и расширения в `.pi/` — локальная разработка репозитория my-pi и сюда
не переносятся.

`WORKFLOW-MANIFEST.md` — личный манифест владельца, общий с my-pi. Это принципы,
а не требования к агенту и не условие допуска изменений.

## Состав

- Skills `codex-tools`, `todo`, `subagents`, `blindreview`, `highreview`,
  `define-goal`. Skills review не вызываются неявно.
- Профили `spotty` и `bossy` в `plugins/scope-focus/agents/`.
- Пять hooks: `SessionStart`, `SubagentStart`, `SubagentStop`,
  `UserPromptSubmit`, `Stop`.
- CLI `tools/read.cjs` и `tools/todo.cjs` на Node.js, кроссплатформенно.
- Системный промпт — отдельный компонент `new-model-instructions.md`, в пакет
  плагина не входит.

## Подача правил

`SessionStart` подаёт root Main `codex-tools` с путями CLI, `todo`, `subagents`
и строку окружения; при resume и compact ещё открытый todo-список.
`SubagentStart` подаёт субагенту только `codex-tools`; роль он берёт из профиля
и брифа. `UserPromptSubmit` подаёт открытый todo-список или напоминание создать
его. `Stop` сначала не даёт Main закончить, пока работает субагент, потом один
раз за ход возвращает модель к пунктам `pending` и `in_progress`.

Правила todo-списка, review и субагентов живут в skills пакета, а не в системном
промпте. Механика инструментов Codex — в `codex-tools`.

## Todo

Root Main ведёт список через `tools/todo.cjs` для задачи, которая меняет файлы
или идёт в несколько этапов. CLI пишет список сессии в
`<CODEX_HOME>/scope-focus-todo/todo-<id сессии>.json`. Вызов CLI делается в том
же `exec`, что и работа, отдельный ход на список не тратится. Работающие
субагенты отмечаются в `agents-<id сессии>/`; записи старше часа и оборванного
процесса ход не держат.

## Субагенты и review

Main пишет код, конфигурацию, документацию и промпты, запускает программы и сам
выбирает способ выполнения. Обычных субагентов он запускает через `spawn_agent`
без ограничений, по своему решению.

Review идёт только по просьбе пользователя: `$blindreview`, `$highreview` или
явно заказанный аудит. Ни Main по своей инициативе, ни release, ни gate
финализации, ни `$define-goal` ревьюера не запускают. Уровня light нет.

| Уровень | Профиль | Модель |
|---|---|---|
| blind | `spotty` | `gpt-6.1-terra / low` |
| high и аудит | `bossy` | `gpt-6.1-terra / medium` |

Оба профиля несут один промпт из `REVIEWER.md` my-pi, адаптированный к инструментам
Codex, и отличаются только моделью и reasoning. Запуск — `spawn_agent` с
`fork_turns: "none"`, бриф самодостаточный: дословные сообщения пользователя,
согласие, объект с первичными источниками, критерий и отклонённые ранее находки.

Каждая находка опирается на дословные цитаты требования и объекта. Находка с
подтверждёнными цитатами исправляется, без них отклоняется с причиной и цитатой.
`CLEAN` принимается только с конкретным блоком `CHECKED:` и без `UNCHECKED:`;
неполный результат дорабатывается тем же ревьюером через `send_input`, а не новым
проходом. После исправлений проход делает свежий ревьюер. Повторов ради уверенности
нет; при сбое запуска или провайдера — один повтор.

## Системный промпт

`new-model-instructions.md` повторяет `SYSTEM.md` my-pi в том же порядке блоков
и добавляет блок Communication в конец. Отличия только в механике Codex:
продукт назван Codex, независимые вызовы идут в один `exec` через `Promise.all`,
файлы правятся через `apply_patch`, промежуточные сообщения — канал `commentary`,
финальный ответ — канал `final`. Подключается ключом `model_instructions_file`.

## Решения

- Review только по просьбе владельца; автоматических ревьюеров нет нигде.
- Только два ревьюера, blind и high; их имена и модели совпадают с my-pi.
- Отдельного review тестов и его профиля в этой поставке нет по решению владельца.
- Skill `approval` и классы micro/small/large убраны; согласование идёт по правилам
  вопросов системного промпта, один вопрос за сообщение, без ответа согласия нет.
- `$define-goal` сохраняет дословные цитаты пользователя и завершается проверками
  критериев из раздела Completion, без ревьюеров.
- Gate финализации при release Main проходит сам: сверка установленных копий и
  документации. Аудит проводит Bossy только по прямому заказу владельца.
- История и отменённые решения хранятся в Git, архивных копий и записей об
  удалении в исходниках нет.
