# Установка

## Состав

Пакет содержит `memory.js`, skill `local-context-memory` и Node.js hooks.
Он хранит checkpoint, этапы работы и точную историю в локальной SQLite-базе.
Код и skill работают из установленного пакета; отдельные профили агентов
не нужны. База, журналы и настройки находятся в одной пользовательской
папке вне пакета.

## Требования

Нужны Codex с поддержкой плагинов и hooks и Node.js 24.5 или новее.
Поддерживаются macOS, Linux и Windows; в Windows используется только Git
Bash, без PowerShell. MCP и отдельный сервер не нужны.

## Первая установка

Установи пакет штатным механизмом Codex и включи его hooks. Подключи штатные
возможности Codex для TokenBudget и перехода в новое окно, если они доступны
в этой версии хоста. Они настраиваются отдельно от нашего плагина;
одноимённый feature flag не включает сам плагин. Не добавляй неизвестные
ключи настроек и не обещай автоматическую замену compaction: плагин её
не реализует.

Настрой доверие к hooks через штатный Codex app-server. Получи определения
через `hooks/list` и запиши нужный trust через `config/batchWrite` в
`hooks.state`: используй точный ключ hook и его `currentHash` как
`trusted_hash`. Меняй только hooks устанавливаемого плагина; уже доверенные
не переписывай. Не обходи trust и не подставляй хеш из прежней версии.

## Проверка после установки

В конце установки устанавливающий агент проверяет подключённые части,
состояние trust и работу всех зарегистрированных hooks на целевой ОС.
В Windows выполняй эту проверку на Windows через Git Bash; запуск на macOS
или Linux не подтверждает работу Windows. Проверяй штатные события Codex,
включая предусмотренное отключение необязательных функций.

Готовность означает, что агент может сохранить checkpoint и восстановить
его через bootstrap вместе со ссылкой на точную запись истории. Проверь
доступность штатного перехода окна, если он подключён. Если нужной возможности
хоста нет, укажи это ограничение; наличие файла плагина не доказывает её
работу.

## Обновление

Обнови файлы пакета целиком. Сохрани существующую пользовательскую папку,
SQLite-базу, журналы, настройки и секреты на прежних местах и в прежнем виде.
Миграция базы выполняется при первом обычном обращении к `memory.js`.
Через app-server согласуй trust изменённых hook-определений; затем выполни
раздел проверки для обновлённых частей. Полную проверку первой установки
без запроса не повторяй. Новые инструкции загружаются в новой задаче;
открытые задачи могут сохранять прежний контекст.
