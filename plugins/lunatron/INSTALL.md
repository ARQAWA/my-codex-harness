# Установка

## Состав

Пакет содержит четыре hook-определения, контракт Main, Node.js CLI для
подготовки контекста и профили `agents/lunatik.toml` и `agents/luntik.toml`.
Lunatik выполняет рабочие команды и простые правки по точному поручению.
Luntik готовит факты и ссылки на исходники. Main владеет решениями, своими
сложными патчами и приёмкой. CLI извлекает фрагменты для ответа Main;
он не вызывает модели, не пишет файлы и не исполняет команды.

Custom catalog и общие instructions — отдельные файлы поставки, не часть
пакета. Их подключение описано ниже; сам пакет не зависит от репозитория разработки.

## Требования

Нужны Codex CLI с поддержкой плагинов, hooks и app-server, Node.js, оба
профиля помощников и отдельно подключённый `properliler` из Scope Focus.
Зависимостей npm нет. Поддерживаются macOS, Linux и Windows; в Windows
используется только Git Bash, без PowerShell. Lunatron и Tritron не должны
работать одновременно.

Установщик должен обеспечить ёмкость пяти дочерних threads: четыре Luna и
один reviewer; Main считается отдельно. Для Codex `0.154.0-alpha.6.2` V2
достаточно:

```toml
[agents]
max_concurrent_threads_per_session = 5
```

В этой версии значение добавляет один к общему лимиту, поэтому effective
итог должен быть не меньше 6. Если уже задан
`[features].multi_agent_v2.max_concurrent_threads_per_session`, он имеет
приоритет и считает Main. Не создавай feature override без существующей
настройки, не снижай больший действующий лимит и учитывай более строгий cap
хоста.

## Первая установка

Найди фактическое имя в поле `name` нужного `marketplace.json`. Личный
marketplace из `~/.agents/plugins/marketplace.json` обнаруживается автоматически:
для него `marketplace add` не нужен, даже если его нет в списке. Если другой
источник ещё не подключён, добавь предоставленный локальный путь или Git URL.
Затем установи пакет:

```bash
codex plugin marketplace list --json
codex plugin marketplace add "<источник>"
codex plugin add "lunatron@<marketplace>" --json
```

Подключи `agents/lunatik.toml` и `agents/luntik.toml` из установленного пакета
в каталог `agents` активного Codex home (обычно `~/.codex/agents`). Подключи
`properliler` из Scope Focus. Используй одного lunatik и до трёх независимых
luntik. Профили не требуют отдельного Fast; не включай Fast у Main.

Для отдельно поставленных custom catalog и общих instructions используй
их актуальные файлы на целевой машине. В корневой части `config.toml`, до
таблиц, задай реальные абсолютные пути:

```toml
model_catalog_json = "<полный путь к codex-model-catalog.json>"
model_instructions_file = "<полный путь к new-model-instructions.md>"
```

Не подставляй путь другой машины, не создавай дубли ключей и не заменяй другие
настройки. В Windows используй пути с `/` либо корректные TOML literal strings.
Если эти компоненты не входят в выбранную поставку, их настройки не добавляются.

Настрой доверие к hooks через штатный Codex app-server. Получи определения
через `hooks/list` и запиши нужный trust через `config/batchWrite` в
`hooks.state`: используй точный ключ hook и его `currentHash` как
`trusted_hash`. Меняй только hooks устанавливаемого плагина; уже доверенные
не переписывай. Не обходи trust и не подставляй хеш из прежней версии.

## Проверка после установки

После установки запусти каждый установленный хук с нужными входными данными
на целевой ОС. Убедись, что он выполняется без ошибок. На Windows используй
Git Bash. На этом проверка закончена.

Запросы к моделям, пробные задачи, переходы контекста и дополнительные
проверочные процедуры в проверку установки не входят.

## Обновление

Обнови пакет через тот же `codex plugin add
"lunatron@<marketplace>" --json`, затем обнови оба packaged profiles из одной
версии. Профиль `properliler` обновляется из Scope Focus отдельно. Сохрани настройки, данные,
сохранённые результаты, артефакты и остальные плагины. Повтори настройки
ёмкости только по правилам требований: не создавай feature override без
существующей настройки, не снижай больший лимит и учитывай host cap.
Профили не требуют отдельного Fast; обычный root режим Main сохраняется.
Через app-server согласуй trust изменённых hook-определений; уже доверенные
не переписывай. Не повторяй bump source version. Затем выполни раздел проверки
для обновлённых частей. Полную проверку первой установки без запроса не
повторяй. Новые инструкции загружаются в новой задаче; открытые задачи могут
сохранять прежний контекст.
