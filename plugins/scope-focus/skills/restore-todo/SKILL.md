# Restore Todo

The root Main reconstructs the list itself. Use this skill after [Restore Session](../restore-session/SKILL.md), or explicitly when a decisions registry for the source session already exists. It creates a work list, not permission to execute it.

1. Read the complete source registry through `Decisions CLI show`. If it has not been rebuilt from the old history, follow Restore Session first. Preserve the distinction between owner decisions, agent proposals, factual evidence and uncertain claims.
2. Use `History CLI` for the immutable source snapshot named in the registry's coverage, with the same source session ID and `--path FILE`. Read every page from the beginning, following the full printed next-page arguments until the explicit end. Do not switch back to the growing live rollout. Include original user and assistant messages, calls, results and compaction markers. Summaries can help navigation but do not replace the original history. Never skip old pages because newer summaries seem sufficient.
3. As you read a history larger than the context window, save a working reconstruction in the OS temporary directory. Track the source cursor, owner requests and decisions, changes of scope, completed results with their evidence, cancellations, unresolved questions, blockers and remaining work. Keep source record references. Resume from that note after compaction, without losing previously covered pages. Keep decision authority in the registry; the working note holds evidence and progress, not new owner decisions.
4. Reconcile the whole history before writing the resulting todo. A proposal is not agreement, an intention or a started command is not completion, and a reported result is not stronger evidence than its source supports. Do not revive cancelled or superseded tasks. Do not mark an item completed without evidence; preserve real uncertainty as a blocker or an unresolved question. Where the task needs current workspace facts to resolve a historical claim, read only those facts. Do not run tests, experiments or project work merely to reconstruct the list.
5. For the current session, use its existing `Todo CLI` to create or reconcile the list under Main Workflow. Keep compatible unfinished items and their progress; do not erase them just because restoration is running. Read closed items when needed. Include only agreed work that remains, with its dependencies, accepted decisions and real blockers. Completed or abandoned historical work is evidence for reconciliation, not a new queue.
6. When restoring another session, do not overwrite the current session's todo. Use that source session's ID explicitly through `CODEX_THREAD_ID` for the todo CLI call, and make the target clear in the report. This restores the selected source session, not a cross-session import.

Missing, unreadable or incomplete history prevents a claim that the whole session was reconstructed. Preserve the existing todo when essential evidence is unavailable and report what is missing. If no agreed work remains, say so; do not invent tasks to populate the list. When the request authorizes restoration only, mark recovered work as blocked awaiting the owner's instruction to continue, so the Stop hook does not turn reconstruction into execution. Stop after restoring the list unless the owner also asked to continue the work.
