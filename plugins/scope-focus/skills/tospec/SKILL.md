# ToSpec

Один skill с деревом обычных вложенных инструкций. Результат — spec.md и
plan.md со встроенными задачами для другого исполнителя. Решение объясняется
пользователю в чате; реализация требует отдельного поручения.

## Обязательное основание

До работы прочитай полностью [Working Standards](../working-standards/SKILL.md).
Применяй каждый пункт ко всем действиям, решениям, документам и переходам;
не заменяй источник выжимкой. Уже доступный актуальный полный текст повторно
не читай; после потери контекста восстанови его до зависимой работы.
Для чата действует [Clear Communication](../clear-communication/SKILL.md):
читай источник только если полный актуальный текст ещё не доступен.

Выбирай самый простой достаточный путь при полном результате. Качество не
разрешает расширять задачу, минимальность — терять требования или работающее
поведение вне заказанного изменения. Эффективность оценивай по источникам
и логике; не проводи замеры и не обещай измеренный или глобальный оптимум.

## Загрузка по этапам

Основной файл задаёт маршрут и общие границы; подробности находятся в шагах,
references и шаблонах. Вложенные файлы не являются самостоятельными skills.
Открывай только текущий шаг и указанные в нём необходимые материалы. Следующий
шаг загружай после выполнения условия выхода текущего, без вопроса о продолжении.
Не вычитывай дерево заранее и не читай шаблон плана во время подготовки спеки.

1. [Разведка](steps/01-research.md).
2. [Спецификация](steps/02-spec.md).
3. [Объяснение решения и согласование](steps/05-approve.md).
4. [Два параллельных Light Review спеки](steps/04-scope-review.md).
5. [План со встроенными задачами](steps/06-plan.md).
6. [Два параллельных Light Review плана и передача](steps/10-final-review.md).

Номера файлов сохранены; порядок задаёт этот маршрут. Объединяй чтение текущего
шага и уже известных нужных ему материалов, когда это возможно. Актуальные
загруженные инструкции переиспользуй; после потери контекста восстанавливай
только необходимые для продолжения источники. Не создавай загрузчик, кеш,
движок состояний, hooks или новые skills для этапов.

## Полномочия и готовность

Пользователь согласует весь текущий смысл спеки. Только после согласия начинаются
два её review; только после двух действительных CLEAN — подготовка плана.
План и его технические решения внутри спеки агент готовит самостоятельно,
без отдельного approval. Новый результат, scope, стоимость, доступ, приватность
или иное изменение согласованного условия возвращается к спеке и согласованию.

Две пары review — явно выбранная процедура ToSpec: одна после согласия на спеку,
другая после завершения плана. Каждая требует два действительных CLEAN по своим
направлениям. Reviewer проверяют инженерные объекты, не стиль пользовательского
сообщения. CLEAN не заменяет согласие и не гарантирует безошибочность.

Храни документы только в точном OS tmp workspace текущей задачи. Не меняй
репозиторий, ветки, настройки или установленные плагины; не запускай реализацию,
commit, push, release, установку, тесты или замеры. Выбор ToSpec не включает
Goal, Task Notebook, cleanup и другие режимы. Действующий Lunatron сохраняет
собственный контракт.

Согласие, основания, ревизии, статусы и проверки хранятся в двух документах,
без реестра, хешей, копий или архива. Готовность требует согласия на текущий смысл
и действительных обеих пар review. При содержательной правке или изменении
решающего факта сними затронутые CLEAN и готовность до зависимого перехода.
Номер документа сам по себе не доказывает актуальность согласия или проверки.
Без обязательного ответа, источника или Spotty останови зависимый переход.
