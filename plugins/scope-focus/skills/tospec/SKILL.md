# ToSpec

Один skill с вложенными шагами для любой задачи, включая аналитическую или
документную без рабочего каталога. Подготовка даёт spec.md и plan.md в OS tmp;
решение объясняется в чате. Отдельное `+++` после готового плана запускает
его выполнение (шаг 07).

## Основание

Gold Standard и Clear Communication уже в контексте из hook; читай файл только
если текста там нет. Применяй Gold Standard ко всем действиям, решениям,
документам и переходам. Выбирай самый простой достаточный путь с полным
результатом: результат минимален, чтение широкое. Существенное неизвестное
разрешай опытом по шагу 01, когда источников недостаточно. Отличай оценку от
наблюдения: не обещай измеренное без замера и глобальный оптимум.

## Шаги и их загрузка

Шаги — вложенные инструкции, не самостоятельные skills. Читай их и шаблоны
одним батчем, без вопроса о продолжении:

- старт: [01](steps/01-research.md), [02](steps/02-spec.md),
  [03](steps/03-approve.md) и [шаблон спеки](templates/spec.md);
- после согласия на спеку: [04](steps/04-spec-review.md),
  [review](references/review.md), [05](steps/05-plan.md),
  [06](steps/06-plan-review.md) и [шаблон плана](templates/plan.md);
- после отдельного `+++`: [07](steps/07-execute.md).

Маршрут: 01 разведка → 02 спека → 03 объяснение и согласие → 04 два Light Review
спеки → 05 план со встроенными задачами → 06 два Light Review плана и
готовность → 07 выполнение. Этот файл — единственная копия маршрута. Загруженный
текст переиспользуй, после потери контекста перечитай нужное. Загрузчик, кеш,
hooks и новые skills не создавай. При доработке ToSpec сверяй весь затронутый
контракт: этот файл, шаги, references, шаблоны, UI и документацию.

## Полномочия и готовность

Пользователь согласует весь смысл спеки. После согласия идут два review спеки;
после обоих CLEAN агент сам готовит план, без отдельного approval, и проводит
два review плана. Новый результат, scope, стоимость, доступ, приватность или
изменение согласованного условия возвращается к спеке и согласованию.

Две пары review — явно выбранная процедура ToSpec: каждая даёт два CLEAN по
своим направлениям. Reviewer проверяют объекты задачи, не стиль сообщения.
CLEAN не заменяет согласие и не гарантирует безошибочность.

Документы и материалы исследования лежат только в workspace задачи в OS tmp.
До подтверждения целевые объекты не меняй: разрешены чтение, временные документы
и изолированный опыт по шагу 01. Явные запреты и методика пользователя
сохраняются. Подготовка не включает Goal и итоговый review; `+++` запускает
шаг 07: Goal, выполнение и один Light Review результата. Notebook и очистка
идут по общим правилам. Действующий Lunatron сохраняет собственный контракт.

Согласие, основания, ревизии, статусы и проверки хранятся в двух документах,
без реестра, хешей и копий. Готовность требует согласия на текущий смысл и обе
пары CLEAN. Содержательная правка или новый решающий факт снимает затронутые
CLEAN и готовность; номер версии актуальность не доказывает. Без ответа
пользователя, нужного источника или доступного Spotty продолжай независимую
работу, зависимый переход жди.

Сокращение подтверждения — только целое пользовательское сообщение `+++`;
внешние пробелы допустимы, цитата, код или часть большего сообщения не подходят.
Оно относится к однозначному текущему готовому плану. Не ищи похожий или
последний workspace; при недостающей связи запроси точный план. Повторное
подтверждение продолжает то же выполнение либо сообщает достигнутый результат,
без второго Goal или повторения операций. Готовность сама выполнение не
разрешает; материалы сохраняются до его завершения.
