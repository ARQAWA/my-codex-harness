# 02. Спецификация

Прочитай только [шаблон](../templates/spec.md). Запиши spec.md текущей задачи
в её OS tmp workspace. Документ предназначен агенту; отдельной человеческой
части в нём нет. Короткое объяснение для пользователя будет в чате на шаге 05.

Опиши проблему, границы, наблюдаемое поведение, сценарии, R-требования и AC-приёмку.
Каждое R опирается на U или необходимое решение D внутри U; каждое AC — на R.
Примеры и исключения не должны вводить скрытое дополнительное поведение.
F подтверждает факт, но не заменяет поручение пользователя.

Для каждого самостоятельного проектного решения зафиксируй D, выбранный вариант,
основания, влияние и вид:
- ПРЯМОЕ — точное указание пользователя U.
- ВЫНУЖДЕННОЕ — другой допустимый вариант нарушает действующее условие;
  назови это условие. Удобство, привычка и готовая библиотека не доказывают единственность.
- ВЫБОР — есть альтернативы; сам рекомендуй самый простой достаточный вариант
  по полным Working Standards, кратко укажи отклонённые варианты и причины.

Новые решения пока предложены. Не возвращай проектирование пользователю и не
спрашивай, какой из трёх вариантов ему выбрать. Неизвестный существенный факт
обозначь Q; вопрос уместен только если его нельзя разрешить доступным исследованием.

Детализируй всё необходимое для результата: условия, данные, интерфейсы, ошибки,
ограничения и проверяемые исходы. Достаточность не равна максимальному объёму.
Не добавляй новые лимиты, миграции, безопасность, fallback, тесты, инфраструктуру
или редкие случаи ради качества. Применимый обязательный контракт укажи с источником.
Проверки не требуют придуманных метрик и запусков для уверенности.

Проверь применимость каждого пункта Working Standards к выбранным решениям.
Выход: точный черновик с основаниями всех R/AC/D; нет скрытого scope и плана работ.
Далее `03-decision-check.md`.
