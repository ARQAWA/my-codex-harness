# 06. План

Вход: точная согласованная спека и её реальные основания. Прочитай только
[шаблон плана](../templates/plan.md). Запиши plan.md рядом со spec.md в OS tmp.
Шаблон задач открывается после завершения этого плана, без промежуточного review.

Применяй каждый пункт Working Standards. Сам выбери существующий достаточный
механизм либо минимальную локальную адаптацию. Оцени эффективность, стоимость
исполнения и производительность теоретически по источникам и логике, без замеров.
Не обещай доказанный глобальный оптимум. Привычка не заменяет обоснование выбора.

Задай конкретный способ реализации, существующие точки изменения, нужные новые
пути с отметкой «создать», порядок и зависимости. Укажи определяющие интерфейсы,
данные, условия ошибок и проверяемые результаты в нужном для исполнения объёме.
Каждый блок плана P связан с R/AC и основаниями; нет несогласованных новых функций,
лишних абстракций, страховочных механизмов, миграций или инфраструктуры.
Сохрани обязательные контракты и работающее поведение вне заказанного изменения;
меньший объём правки не оправдывает потерю нужной функции.

Технические D в границах спеки решай сам; запиши выбранный вариант, источники,
влияние, альтернативы и короткую причину. Статус — решение агента внутри spec vN,
а не одобрение пользователя. Отдельное approval плана не нужно.
Изменение результата, scope, доступа, стоимости или иного согласованного условия
не является рутинным решением: останови зависимый блок и вернись к 02–05.

Устрани существенные пробелы разведкой либо конкретным обоснованным решением.
Не передавай исполнителю «выбрать позже», TODO по архитектуре или неразрешённую
зависимость. Применимые правила и точные источники доступны другому агенту.
Способ проверки AC следует Working Standards: чтение и логика по умолчанию;
тесты, сборки и запуски планируются только при отдельном действующем основании.
На этапе подготовки они не выполняются.

Выход: содержательно завершённый план по spec vN; каждый необходимый блок
определён, основан на запросе и осуществим в заявленных условиях. Статус —
`ЧЕРНОВИК` до review всего комплекта. Далее `08-tasks.md`, без отдельного
review плана и без вопроса пользователю.
