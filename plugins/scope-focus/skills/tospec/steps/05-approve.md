# 05. Получить согласование

Вход: текущая проверенная версия `spec.md`.
Если осталось существенное Q о поведении, границах или критерии готовности,
задай нужный вопрос. Ответ, меняющий смысл, возвращает к 02–04.
Чисто инженерный вопрос можно оставить планированию, если он не меняет эти условия.

Покажи человеческую часть и дай доступ к обеим частям целиком с номером версии.
Материальные неоднозначные выборы должны быть явно показаны пользователю,
не только спрятаны в техническом приложении. Для них сохраняй D-идентификаторы.
Не заставляй читать весь технический блок в чате, но не проси одобрить невидимый файл.

Спроси один раз: «Согласовываешь spec vN целиком, включая показанные решения D-…?
После этого подготовлю план и задачи, без запуска разработки».
Если значимых выборов нет, не добавляй пустое перечисление D.

Пауза обязательна. Предыдущая просьба «создай спеку», молчание, «сохрани»,
«продолжай обсуждение» и согласие с одним пунктом не утверждают ещё не показанную
полную версию. Однозначное «да» в ответ на этот вопрос достаточно. Общее согласие
не расширяет исходный scope и не заменяет устранение нарушений на шаге 04.

После ответа сохрани только статус `СОГЛАСОВАНО`, версию и доступную точную цитату
согласия. Содержание обеих частей не меняй. Показанные ВЫБОРЫ этой версии считаются
принятыми через запись согласования; не переписывай их задним числом как ПРЯМЫЕ.

Если пользователь поправил документ, подготовь новую версию и пройди 02–05
для изменённого результата. Новые требования допустимы только от пользователя,
с новым U-источником. При продолжении по сохранённому файлу одного слова
«СОГЛАСОВАНО» без доступного основания недостаточно.

Выход: явное согласие на доступную полную текущую версию; блокирующих Q нет.
Только теперь открой `06-plan.md` и автоматически продолжи планирование.
