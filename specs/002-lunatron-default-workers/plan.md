# План правок: рабочие форки Lunatron по умолчанию

**Статус:** согласовано
**Основа:** [спецификация](spec.md)

## Суть

Режим `default-on` уже выдаётся hook. Нужно убрать конфликт инструкций,
из-за которого Main не делегирует работу, и закрыть обход правила моделей
через фиксированный профиль Luntik на Luna `xhigh`.

## Где менять

| Место | Правка |
| --- | --- |
| Глобальный и репозиторный `AGENTS.md` | Явно разрешить рабочие форки при активном Lunatron: это исключение допускает `multi_agent_mode`. |
| `plugins/lunatron/agents/luntik.toml` | Закрепить Luna `medium` для узких вопросов к выбранным данным. |
| `plugins/lunatron/hooks/lunatron.cjs` | Уточнить выбор простого/сложного исполнителя и запретить Luna `xhigh` при Main Sol/Astra. |
| `AGENTS.md`, `install-instructions/lunatron.md` | Описать одно и то же правило без противоречий. |

## Порядок

1. **Разрешение на делегирование.** В установку и обновление Lunatron добавить
   короткое правило для `<active-codex-home>/AGENTS.md`: при
   `LUNATRON_STATE=ACTIVE` рабочие форки разрешены без запроса `LNT1`.
   Сохранить остальные записи и не дублировать это правило при обновлении.
   В репозиторном `AGENTS.md` заменить запрет самостоятельной делегации
   таким же условным разрешением. `multi_agent_mode` уже допускает явное
   поручение из применимого `AGENTS.md`. Если на целевом хосте оно всё же
   не действует, устранить внешний конфликт до заявления о готовности.
2. **Модели.** Поменять профиль Luntik с `xhigh` на `medium`. В тексте hook
   оставить Luna Medium для простых блоков и узких вопросов к данным.
   Сложный вопрос передавать рабочему форку по таблице из спецификации.
   Сохранить уже работающий `default-on` и поведение `LNT0`/`LNT1`.
3. **Согласованность.** Обновить действующее описание Lunatron в
   `AGENTS.md` и инструкции установки. Убрать утверждение, что Luntik
   всегда работает на `xhigh`. Не менять правила reviewer.
4. **Приёмка.** Сверить итоговые инструкции, профиль и hook с каждым
   сценарием спецификации. Выполнить обязательный для репозитория финальный
   light review. При заказанном внедрении выполнить положенную проверку.
   Release и установку выполнять только по отдельному явному запросу:
   правка исходников сама не меняет установленную копию.

## Граница плана

Этот план задаёт объём правок. Сам документ не запускает реализацию,
проверочные чаты, release или установку; для них нужен отдельный заказ.
