# Спецификация: filesystem-search со штатными MCP

**Область:** только `filesystem-search`. Для него владелец разрешил узкое
исключение из общего запрета MCP.

## Результат

Агент сохраняет прежние правила поиска. Код и связи ищет через Codebase Memory
(CBM), текст и файлы — через `tgrep`, синтаксис при необходимости — через
`ast-grep`. Все три инструмента подключены как штатные MCP-серверы. Плагин
не поддерживает собственные поисковые CLI-обёртки, демоны, watcher, guards,
hooks и locks. Он не готовит индекс особым действием при первом запросе.

**Все постоянные данные поисковых индексов, созданные этой интеграцией,
должны находиться в пользовательском кэше.** Индексы не хранятся в
репозитории или рабочем каталоге агента. Область индексации выбирают сами
серверы по своим штатным правилам; плагин не обещает точный корень проекта
Codex, единый индекс для подпапок или запрет поиска вне проекта.

## Сценарии и проверка

### Правила поиска

- Если точный путь уже известен, агент читает его напрямую.
- Для кода, символов, вызовов и связей первым служит CBM. Для текста,
  имён файлов, документации и конфигурации — `tgrep`. При недостаточном
  ответе индекса синтаксис ищется через `ast-grep` по текущим файлам.
- Для строго актуального текста, полного охвата и отрицательных выводов
  агент проверяет исходные файлы прямым чтением или узким обычным поиском.
  Старый граф CBM нельзя представлять как текущий.
- CBM может индексировать папку без Git, но его штатный watcher не
  обновляет в ней граф автоматически. Плагин не добавляет свой watcher.
  [Индексация](https://github.com/DeusData/codebase-memory-mcp/blob/64c23fab6c3eba3de226355c0ca1ff750116edab/src/mcp/mcp.c#L17697-L17752),
  [watcher](https://github.com/DeusData/codebase-memory-mcp/blob/64c23fab6c3eba3de226355c0ca1ff750116edab/src/watcher/watcher.c#L1464-L1472).

В YAML `description` файла
[`SKILL.md`](../../plugins/filesystem-search/skills/filesystem-search/SKILL.md)
нужно перенести **дословно, без HTML-маркеров**, следующий текст из прежнего
блока `FILESYSTEM_SEARCH_GLOBAL_ROUTING`:

```text
# Mandatory filesystem discovery routing

Before any command or tool call whose purpose is to discover files, symbols,
text, callers, dependencies, impact, or source context, load the
`filesystem-search` skill and follow its routing. This gate is mandatory and
comes before `rg`, `grep`, `find`, globs, AST scripts, or Codebase Memory CLI.
Read an already known exact path directly when discovery is not needed.
```

Слова `Codebase Memory CLI` сохраняются как часть точного старого текста.
Они не разрешают возвращать CLI-обёртку: после перехода используются MCP.
Старый полный блок удаляется из исходного и активного `AGENTS.md` при
установке или обновлении. Остальной текст сохраняется. Установщик `tgrep`
вправе оставить **свой** штатный раздел в пользовательском `AGENTS.md` и
свой `SessionStart` hook: это не старый блок `filesystem-search` и не место
хранения индекса.

## Требования

### Штатное хранение и подключение

- Для `tgrep` использовать официальный `install-agent.sh install --agent
  codex --scope user`. Пользовательская установка держит сервисный индекс
  в `$XDG_CACHE_HOME/tgrep-agent/<key>/index` (обычно `~/.cache`).
  Проектная установка создаёт `<repo>/.tgrep-agent/`, поэтому она не
  подходит. Прямой `tgrep serve .` не подменяет эту интеграцию.
  [Источник: tgrep agent integration](https://github.com/microsoft/tgrep/blob/main/scripts/agent/README.md).
- Для CBM использовать штатный MCP. Его индекс по умолчанию хранится в
  `~/.cache/codebase-memory-mcp`. Не менять штатные параметры индексации.
  При установке включить штатную автоиндексацию командой
  `codebase-memory-mcp config set auto_index true`, чтобы CBM строил граф при
  подключении MCP. Автоиндексация сохраняет стандартное `persistence: false`.
  `persistence` — параметр отдельного вызова MCP `index_repository`, а не
  глобальная настройка. При явном вызове передавать `persistence: false`.
  После настройки проверить значение командой
  `codebase-memory-mcp config get auto_index`.
  [Настройки CBM](https://github.com/DeusData/codebase-memory-mcp/blob/main/docs/CONFIGURATION.md).
- `ast-grep` подключается через [официальный MCP](https://github.com/ast-grep/ast-grep-mcp)
  и не хранит постоянный поисковый индекс.

**Переход со старого экспорта CBM.** Владелец разрешил удалить старый экспорт.
Для известного затронутого репозитория до индексации CBM нужно установить
точный путь и подтвердить, что `<repo>/.codebase-memory/graph.db.zst` — старый
созданный CBM экспорт. Удалить только этот файл. Не удалять `.gitattributes`
или другие данные. Если принадлежность файла неясна, не удалять его и не
заявлять для этого репозитория, что индекс хранится только в пользовательском
кэше. Не требуется искать все репозитории или автоматически удалять экспорт
в неизвестных корнях.
[Источник: CBM team-shared graph artifact](https://github.com/DeusData/codebase-memory-mcp/blob/main/README.md#team-shared-graph-artifact).

Официальная MCP-интеграция `tgrep` документирована для Linux и macOS.
Работу её MCP на Windows не обещать и не строить собственный адаптер ради
этого. [Источник: tgrep agent integration](https://github.com/microsoft/tgrep/blob/main/scripts/agent/README.md).

После индексации проверить в известном затронутом репозитории, что старый
`.codebase-memory/graph.db.zst` не появился снова. Не искать экспорты в
неизвестных корнях и не проверять другие репозитории.

## Критерии успеха

1. На поддерживаемой ОС агент видит три штатных MCP-инструмента и применяет
   правила поиска выше без прежних обёрток плагина.
2. Постоянные данные новых индексов CBM и `tgrep` находятся в
   пользовательском кэше; интеграция не создаёт индекс в репозитории или
   рабочей папке агента. В известном затронутом репозитории старый экспорт
   удалён только после подтверждения его точного пути и принадлежности;
   после индексации он не появился снова.
   Неясный по принадлежности файл не удалён, и для такого репозитория
   гарантия хранения только в пользовательском кэше не заявляется.
3. Новый `description` позволяет агенту выбрать skill до поиска неизвестного
   файла или символа. Старого блока `filesystem-search` в `AGENTS.md` нет;
   штатный раздел `tgrep` не принимается за него.
4. Установка и обновление сохраняют чужие настройки и текст, подключают
   штатные серверы и не оставляют прежний runtime поиска.
