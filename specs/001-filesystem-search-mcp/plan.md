# План: filesystem-search со штатными MCP

**Основание:** [spec.md](spec.md).

1. **Принять документы.** Сверить каждую критическую точку с исходниками
   серверов и light reviewer: правила поиска, пути постоянных индексов,
   существующий экспорт CBM, маршрут через `description` и состав штатной
   установки. Затем провести полный high review `spec.md` и `plan.md`:
   согласованность, отсутствие лишних и придуманных требований. Только
   после его одобрения начать правки. Владелец разрешил удаление старого
   экспорта CBM только для известного затронутого репозитория после
   подтверждения точного пути и принадлежности файла.
2. **Подключить штатные серверы и хранение.** Установить `tgrep` в
   пользовательской области его официальным installer, подключить CBM и
   `ast-grep` штатно и оставить штатные параметры индексации. Использовать
   пользовательские кэши без проектной установки `tgrep` и без экспорта
   графа CBM в репозиторий. Для построения графа при подключении MCP включить
   штатную автоиндексацию командой `codebase-memory-mcp config set auto_index
   true` и проверить её через `codebase-memory-mcp config get auto_index`.
   Автоиндексация использует стандартное `persistence: false`; при явном
   вызове MCP `index_repository` также передавать `persistence: false`.
   Не задавать `persistence` через `config set`.
   До индексации CBM в известном затронутом
   репозитории подтвердить, что `<repo>/.codebase-memory/graph.db.zst` —
   старый экспорт CBM, и удалить только этот файл. Не удалять
   `.gitattributes` или другие данные. Если принадлежность неясна, оставить
   файл и не заявлять для этого репозитория гарантию хранения только в
   пользовательском кэше. Не искать все репозитории и не удалять экспорты
   в неизвестных корнях. После индексации проверить, что экспорт не появился
   снова. Проверить критические условия через light reviewer,
   весь крупный блок — через high reviewer.
3. **Заменить плагин и инструкцию.** Перевести skill на MCP, сохранить
   правила выбора и свежести, перенести точный текст прежнего блока
   `FILESYSTEM_SEARCH_GLOBAL_ROUTING` в YAML `description` без HTML-маркеров.
   Удалить прежние поисковые обёртки, демоны, watcher, guards, hooks,
   locks и managed-блок `filesystem-search` из исходного `AGENTS.md`.
   Установка и обновление удаляют старый блок из активного `AGENTS.md`,
   сохраняя остальное. Штатные раздел и hook `tgrep` остаются его
   собственными. Обновить только прямо зависимые установочные тексты;
   закрепить узкое разрешение MCP для `filesystem-search`. Проверить
   критические условия через light reviewer, крупный блок — через high
   reviewer.
4. **Принять и выпустить.** Сверить приёмку спецификации, затем отдать
   всю работу astro reviewer. После устранения замечаний пройти
   обязательный `finalize-work` gate с CLEAN. Далее выполнить source
   release, установку и её проверки по release-процедуре, затем `push`
   только относящихся к задаче изменений. Не затрагивать чужую работу.
