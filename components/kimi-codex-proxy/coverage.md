Этот файл — контрольная карта для реализации по [самодостаточной спецификации](spec.md). Он описывает **путь модельного запроса**, а не все функции приложений. Метки `K` и `C` указывают на исходники опубликованных релизов: [Kimi Code 2.1.1](https://github.com/MoonshotAI/kimi-code/tree/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f), commit `f67e6398fb3210ad8ace970e2dfd5bcc984ed61f`; [Codex CLI 0.157.1](https://github.com/openai/codex/tree/36650394c5b38c2990ccf2a3457165ca3e9d9726), commit `36650394c5b38c2990ccf2a3457165ca3e9d9726`. Все ссылки ниже закреплены на этих commit. `Мост` — требование адаптера, а не утверждение, что такое преобразование уже есть в CLI. Неподтверждённое поведение backend отмечено прямо.

## Сквозная сверка и предел точности

1. **Форма ответа и следующего запроса.** Kimi не возвращает backend output items побайтно: она собирает своё assistant message и снова понижает его в OpenAI wire. Поэтому `prompt_cache_key` и raw `response_id` не доказывают совместимое продолжение. Мост сверяет внешний запрос с ожидаемой Kimi-проекцией, потом строит логическую Codex-историю и применяет C11–C13. При любой неоднозначности отправляет полный input. [Kimi lowering](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/packages/agent-core-v2/src/human/llm/requester/bases/openai-responses/lower.ts#L132-L221), [CLI comparison](https://github.com/openai/codex/blob/36650394c5b38c2990ccf2a3457165ca3e9d9726/codex-rs/core/src/client.rs#L330-L405).
2. **Выбранное отклонение.** Kimi присылает completion cap; Codex CLI `ResponsesApiRequest` его не имеет. Удаление поля — прямое решение пользователя, а не полная семантическая эквивалентность внешнего лимита.
3. **Медиа.** Нативные Codex items имеют text, image, audio, output_text; video-типа нет. Inline mp3/wav можно преобразовать в `input_audio.audio_url` с data URI. `input_file.file_url` можно передать как URL в это строковое поле, но исходники CLI не доказывают, что ChatGPT backend примет удалённый audio URL. Для Chat video эквивалентного нативного item нет; это граница контракта, которую нельзя скрывать словом «exactly». [Kimi Chat lower](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/packages/agent-core-v2/src/human/llm/requester/bases/openai/lower.ts#L1-L56), [Codex ContentItem](https://github.com/openai/codex/blob/36650394c5b38c2990ccf2a3457165ca3e9d9726/codex-rs/protocol/src/models.rs#L878-L897).
4. **Контекст Codex CLI.** CLI знает собственные базовые инструкции, model info, installation/window/thread/turn IDs, authentication и отдельные внутренние возможности. Kimi wire не содержит всех этих данных. Мост должен создавать свои устойчивые session/thread IDs и использовать доступный Codex auth; он не должен выдумывать значения чужого CLI-сеанса. Поэтому «как Codex CLI» означает тот же **проверенный способ подготовки и отправки** поддержанных полей, а не идентичность всех внутренних метаданных CLI. [metadata](https://github.com/openai/codex/blob/36650394c5b38c2990ccf2a3457165ca3e9d9726/codex-rs/core/src/responses_metadata.rs#L231-L370), [request builder](https://github.com/openai/codex/blob/36650394c5b38c2990ccf2a3457165ca3e9d9726/codex-rs/core/src/client.rs#L888-L1005).
5. **Проверка без исходников backend.** Отмеченные source-факты говорят, что отправляют и читают два клиента. Они не доказывают внутреннее расписание ChatGPT, абсолютное равенство задержек, принятие всех моделей, remote audio URL или произвольных `extraParams`. Эти утверждения в спецификации не должны появляться как гарантии.

Для будущей перепроверки каждый ID нужно сопоставить с релизом источника, разделом спецификации и реализацией. Изменение версии любого клиента требует повторной сверки затронутых строк; эта карта фиксирует указанные commit, а не будущий неизменный контракт.
