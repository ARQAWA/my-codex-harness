# Установка

## Состав

Пакет содержит правила работы, skills и профили проверяющих
`agents/spotty.toml`, `agents/smarty.toml`, `agents/bossy.toml`.
Task Notebook автоматически хранит лёгкое полезное состояние задачи при
поправках, discovery, ожиданиях, передаче и смене контекста. Достаточный источник
переиспользуется; Goal и короткая задача сами по себе Notebook не требуют.
Прямой $task-notebook требует ведения, явный запрет имеет приоритет.
`gold-standard` (Золотой стандарт) собирает рабочие принципы в исходных формулировках:
полный результат самым простым, коротким, быстрым и прямым способом.
Применяется перед анализом, планированием, проектированием, реализацией и
проверкой. Доступны штатный автовыбор Codex и ручной вызов
`$gold-standard`; сам автовыбор на каждом ходе не гарантирован. Стандарт требует
удалять связанные устаревшие части согласованной переделки в затронутой области,
сохраняя пользовательские данные, чужую работу, необходимые доказательства
и обязательное поведение. Отдельный
`cleanup-notebook` по прямому публичному вызову удаляет весь notebook текущей
сессии. Автоматический scope=current-task очищает только доказанные расходные
записи завершённой задачи после её временных материалов; прежние задачи,
результаты, нужные доказательства/ссылки и указания сохранить имеют приоритет.
cleanup-task автоматически удаляет только известные расходные материалы этой
задачи после результата и обязательных проверок. При отсутствии целей процедуры
не запускаются; пауза и готовность плана сохраняют нужные входы.
Notebook и HTML-отчёты создаются только во временной папке ОС.

`clear-communication` задаёт короткие осмысленные сообщения в чате для всех задач.
Промежуточные обновления нужны при существенном результате, изменении подхода,
важной неопределённости, блокере или необходимости ответа пользователя. Само
использование инструментов, выбор skill и прошедшее время сообщения не требуют.

Три plugin hooks — `SessionStart`, `UserPromptSubmit`, `SubagentStart` — читают
полные `gold-standard/SKILL.md` и `clear-communication/SKILL.md` из установленного
пакета при старте/возобновлении, clear, compact, новом ходе и запуске субагента.
В каждом определении `additionalContextLimit = 32768`. Они работают глобально
там, где включён пакет и доверены эти hooks; `AGENTS.md` для подключения не меняется.
Правила применяются всем агентам; точные форматы ревьюеров, машинные данные
и подробные документы не обрезаются. Hook дополнительно подаёт настоящий
session_id и вычисленный OS tmp locator; не читает prompt/transcript/Notebook
и не создаёт/удаляет записи. Путь Main имеет приоритет у назначенного владельца
дочернего блока. Подача стандарта задаёт условный выбор Notebook/cleanup, но
не включает Goal, review или посторонние действия и не гарантирует следование модели.

$tospec универсален для любых задач, включая аналитику и документы без
репозитория. Агент исследует проблему и выбирает решение по полному Gold Standard.
Если существенного основания нельзя получить чтением и логикой, сам проводит
минимальный безопасный discovery, проверку гипотезы, короткий MVP, релевантный тест
или измерение. Опыт не обязателен при известном ответе. Все его файлы, выводы,
кэши и состояние остаются в отдельной временной среде, без воздействия на другие
части системы, реальных секретов и подключённых рабочих данных. Временная папка
не заменяет изоляцию; при невозможности безопасного опыта называется ограничение.
Явные запреты запусков и выбранный пользователем метод сохраняются.

Один skill содержит обычные вложенные инструкции с последовательным файловым
порядком 01–07. Общий маршрут находится в skills/tospec/SKILL.md; текущий этап
и нужные материалы загружаются по входным условиям. Будущие инструкции заранее
не читаются, актуальный доступный текст переиспользуется. При доработках сверяется
весь непосредственно затронутый контракт шагов, references, шаблонов, UI
и документации. Программного загрузчика, новых hooks или отдельных skills нет.

Агент готовит спеку и объясняет решение по steps/03-approve.md: основания,
реальные альтернативы и один понятный вопрос в чате. Общий стиль остаётся
в clear-communication. После согласия на весь смысл два параллельных Spotty
проверяют требования/обоснованность и полный Gold Standard. После обоих CLEAN
агент самостоятельно готовит план со встроенными достаточными задачами,
без отдельного approval. Затем два свежих Spotty параллельно проверяют план
по спеке и стандарту. Каждый — gpt-6.1-sol / low, read-only без истории Main;
стиль чата не проверяется. Принятые существенные замечания исправляются одним
блоком, затронутые проверки повторяются свежими Spotty до CLEAN.

v1 — первое предъявление; пользовательский раунд содержательных поправок
повышает vN. План и задачи имеют общую pN. Внутренний fix не повышает vN,
но новый смысл или решающий факт снимает зависимые CLEAN и готовность.
Новый согласуемый смысл сначала получает согласие; точное условное согласие
после внесения поправки не требует повторного вопроса при отсутствии нового выбора.

spec.md и plan.md хранятся в уникальном проверенном os.tmpdir()/scope-focus-tospec-*.
Готовность требует согласия и обеих пар CLEAN. Затем отдельное сообщение +++
подтверждает выполнение именно этого плана: native Goal и полный Gold Standard →
один свежий Spotty через Light Review → допустимый cleanup → Goal complete.
Notebook условен по полезному состоянию; cleanup skills читаются только при
доказанных расходных целях, Notebook удаляется лишь в current-task scope. Execution step и helpers
до подтверждения не загружаются. Повторное +++ не дублирует выполнение.

При наличии Notebook хранит полезные операционные записи и ссылки на primary
документы, без технической копии; отдельные work/report необязательны. Без него
primary plan хранит достаточный статус. Notebook использует своё OS tmp
пространство и не является третьим техническим документом ToSpec. Приёмка сверяет весь фактический результат
с исходным заказом, поправками, спекой, планом и связанными документами;
принятые существенные нарушения исправляются до одного CLEAN. Обязательные gates
и отдельно выбранные reviews сохраняются; совмещение допустимо только при
совпадении полного объекта, профиля и критериев. Незавершённые планы сохраняются;
очистка удаляет только доказанные расходные материалы данного выполнения, сохраняя
результат, необходимые доказательства, чужие и прежние Notebook записи.
Тесты и другие эмпирические проверки исполнения требуют своего явного основания.

Review-skills запускаются явно либо как обязательный этап явно выбранного ToSpec:

| Skill | Профиль и модель | Чистых проходов |
|---|---|---|
| `$light-review-cycle` | Spotty: `gpt-6.1-sol / low` | 1 |
| `$blind-review-cycle` | Smarty: `gpt-6.1-sol / medium` | 1 |
| `$high-review-cycle` | Bossy: `gpt-6.1-sol / xhigh` | 1 |

Все три skills имеют общий read-only контракт: `$blind-review-cycle` хранит
его и запускает Smarty, а Light и High читают его, сохраняя своих reviewers.
Каждый явно выбранный цикл требует один CLEAN на checkpoint; после принятых
замечаний исполнитель исправляет результат и начинает свежий проход.

Системный промпт — отдельный компонент поставки, не часть плагина.
После repo-level setup runtime-пакет самодостаточен и не зависит
от документации репозитория.

## Требования

Нужны Codex CLI с поддержкой плагинов и hooks, Node.js и отдельно
подключённые профили `spotty`, `smarty`, `bossy`. Поддерживаются macOS, Linux
и Windows; в Windows используется только Git Bash, без PowerShell.
Для автоматической подачи стандарта и общения должны быть разрешены hooks
и доверены их текущие определения. Сам `allow_implicit_invocation: true` не гарантирует загрузку skill.

## Первая установка

Найди фактическое имя в поле `name` нужного `marketplace.json`.
Личный marketplace из `~/.agents/plugins/marketplace.json` обнаруживается
автоматически: для него `marketplace add` не нужен, даже если его нет в списке.
Если другой источник ещё не подключён, добавь
предоставленный локальный путь или Git URL. Затем установи пакет:

```bash
codex plugin marketplace list --json
codex plugin marketplace add "<источник>"
codex plugin add "scope-focus@<marketplace>" --json
```

Подключи `agents/spotty.toml`, `agents/smarty.toml` и `agents/bossy.toml`
из установленного пакета в каталог `agents`
активного Codex home (обычно `~/.codex/agents`). Остальные профили сохраняются.

Через штатный Codex app-server `hooks/list` найди три текущих определения
hooks инструкций Scope Focus именно этого пакета. После штатного review/trust запиши
через `config/batchWrite` их точные ключи в `hooks.state`, `enabled = true` и
`trusted_hash = currentHash` текущего определения. Уже совпадающие записи
не переписывай. Не обходи trust и не меняй hooks других компонентов.
Если политика среды запрещает hooks, не обходи её и не объявляй автозагрузку готовой.

Если системный промпт входит в заказанную установку или обновление, выполни
[его отдельную инструкцию](system-prompt.md) той же ревизии. Иначе его файл
и настройки не меняй.

## Проверка после установки

На целевой ОС проверь установленный пакет, доступность skills и трёх профилей,
наличие `hooks/communication.cjs`, `skills/gold-standard/SKILL.md`
и `skills/clear-communication/SKILL.md`.
По `hooks/list` проверь, что все три текущих hook включены, доверены и ссылаются на
установленный пакет.
На Windows используй Git Bash. Эти наблюдения подтверждают подключение;
они не доказывают качество всех будущих ответов модели.

Запросы к моделям, пробные задачи, переходы контекста и дополнительные
проверочные процедуры в проверку установки не входят.

## Обновление

Обновление из актуального источника использует ту же команду
`codex plugin add "scope-focus@<marketplace>" --json`. Обнови пакет и отдельно
установленные профили `spotty`, `smarty`, `bossy` из одной версии.
Примени процедуру trust выше для изменившихся определений hooks инструкций Scope Focus;
сохрани остальные hooks и настройки. Изменение исходников само по себе не означает
обновления runtime-копии; source release выполняется отдельной процедурой.
Если заказано обновление системного промпта, выполни
[его инструкцию](system-prompt.md). Если файлы уже совпадают, повторная запись
не нужна.
После установки совпадающей версии удали только устаревший активный
`agents/properliler.toml`, если он остался от предыдущего пакета Scope Focus;
все остальные профили сохрани.

Сохрани остальные профили, настройки, notebook и данные. При явно выбранном
переносе старого действующего notebook в OS tmp сохрани task key, содержимое
и ссылки на его материалы; не удаляй неизвестные старые notebook или отчёты.
Существующие спецификации из репозитория автоматически не мигрируют и не удаляются.
Проверь обновление по разделу выше. Новые инструкции ToSpec загружаются в новой
задаче; открытая задача может сохранять прежний маршрут. Hook инструкций Scope Focus
читает оба полных текущих установленных источника при каждом своём событии.
