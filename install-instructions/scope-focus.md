# Установка

## Состав

Пакет содержит правила работы, skills и профили проверяющих
`agents/spotty.toml`, `agents/smarty.toml`, `agents/bossy.toml`.
Task Notebook хранит план и прогресс длительной задачи при явном выборе
пользователя. Goal Memory заменён этим skill.
`working-standards` собирает рабочие принципы в исходных формулировках:
полный результат самым простым, коротким, быстрым и прямым способом.
Применяется перед анализом, планированием, проектированием, реализацией и
проверкой. Доступны штатный автовыбор Codex и ручной вызов
`$working-standards`; автовыбор на каждом ходе не гарантирован. Отдельный
`cleanup-notebook` удаляет весь notebook текущей сессии только по явному вызову.
Notebook и HTML-отчёты создаются только во временной папке ОС.

`clear-communication` задаёт короткие осмысленные сообщения в чате для всех задач.
Три plugin hooks — `SessionStart`, `UserPromptSubmit`, `SubagentStart` — подают
его полный текст из установленного пакета при старте/возобновлении, clear, compact,
новом ходе и запуске субагента. Они работают глобально там, где включён пакет
и доверены эти hooks; `AGENTS.md` для подключения не меняется. Каждый ответ
подчинён правилам общения, но точные форматы ревьюеров, машинные данные
и подробные документы не обрезаются.
Hooks подают инструкции, а не гарантируют безошибочное поведение любой модели.

`$tospec` сам исследует проблему и выбирает решение по полным Working Standards.
Два штатных Light Review проверяют инженерное качество: сначала спеку, затем
весь комплект со спекой, планом и задачами. Reviewer не оценивает стиль чата.
После первого CLEAN внутренний файл `steps/05-approve.md` задаёт предъявление:
решение, основания, реальные альтернативы и один понятный вопрос прямо в чате.
Общий стиль остаётся в `clear-communication`; внутренний шаг отдельно не вызывается.
Пользователь согласует спеку; план и задачи агент готовит без отдельных approval
и review. v1 означает первое предъявление; номер растёт только от пользовательского
раунда содержательных поправок. Смысловой внутренний fix отзывает проверки, но не
повышает номер.
Точное «да с поправкой» действует после её внесения и перепроверки без нового вопроса;
новый смысл требует согласия даже при том же vN. Шаги и шаблоны читаются по мере работы.
Для разведки нужен уже подключённый `filesystem-search`; ToSpec его не устанавливает.
`spec.md`, `plan.md`, `tasks.md` — документы для агента в уникальном
`os.tmpdir()/scope-focus-tospec-*`, вне репозитория. После завершения исполнения
явно вызванный `cleanup-task` удаляет только подтверждённые материалы этой задачи.
Конец подготовки не запускает удаление или реализацию.

Review-skills запускаются явно либо как обязательный этап явно выбранного ToSpec:

| Skill | Профиль и модель | Чистых проходов |
|---|---|---|
| `$light-review-cycle` | Spotty: `gpt-6.1-sol / low` | 1 |
| `$blind-review-cycle` | Smarty: `gpt-6.1-sol / medium` | 1 |
| `$high-review-cycle` | Bossy: `gpt-6.1-sol / xhigh` | 1 |

Все три skills имеют общий read-only контракт: `$blind-review-cycle` хранит
его и запускает Smarty, а Light и High читают его, сохраняя своих reviewers.
Каждый явно выбранный цикл требует один CLEAN на checkpoint; после принятых
замечаний исполнитель исправляет результат и начинает свежий проход.

Системный промпт — отдельный компонент поставки, не часть плагина.
После repo-level setup runtime-пакет самодостаточен и не зависит
от документации репозитория.

## Требования

Нужны Codex CLI с поддержкой плагинов и hooks, Node.js и отдельно
подключённые профили `spotty`, `smarty`, `bossy`. Поддерживаются macOS, Linux
и Windows; в Windows используется только Git Bash, без PowerShell.
Для автоматического общения должны быть разрешены hooks и доверены их текущие
определения. Сам `allow_implicit_invocation: true` не гарантирует загрузку skill.

## Первая установка

Найди фактическое имя в поле `name` нужного `marketplace.json`.
Личный marketplace из `~/.agents/plugins/marketplace.json` обнаруживается
автоматически: для него `marketplace add` не нужен, даже если его нет в списке.
Если другой источник ещё не подключён, добавь
предоставленный локальный путь или Git URL. Затем установи пакет:

```bash
codex plugin marketplace list --json
codex plugin marketplace add "<источник>"
codex plugin add "scope-focus@<marketplace>" --json
```

Подключи `agents/spotty.toml`, `agents/smarty.toml` и `agents/bossy.toml`
из установленного пакета в каталог `agents`
активного Codex home (обычно `~/.codex/agents`). Остальные профили сохраняются.

Через штатный Codex app-server `hooks/list` найди три текущих определения
коммуникационных hooks именно этого пакета. После штатного review/trust запиши
через `config/batchWrite` их точные ключи в `hooks.state`, `enabled = true` и
`trusted_hash = currentHash` текущего определения. Уже совпадающие записи
не переписывай. Не обходи trust и не меняй hooks других компонентов.
Если политика среды запрещает hooks, не обходи её и не объявляй автозагрузку готовой.

Если системный промпт входит в заказанную установку или обновление, выполни
[его отдельную инструкцию](system-prompt.md) той же ревизии. Иначе его файл
и настройки не меняй.

## Проверка после установки

На целевой ОС проверь установленный пакет, доступность skills и трёх профилей,
наличие `hooks/communication.cjs` и его исходного `clear-communication/SKILL.md`.
По `hooks/list` проверь, что все три текущих hook включены, доверены и ссылаются на
установленный пакет. Старые hooks прежней общей политики не возвращаются.
На Windows используй Git Bash. Эти наблюдения подтверждают подключение;
они не доказывают качество всех будущих ответов модели.

Запросы к моделям, пробные задачи, переходы контекста и дополнительные
проверочные процедуры в проверку установки не входят.

## Обновление

Обновление из актуального источника использует ту же команду
`codex plugin add "scope-focus@<marketplace>" --json`. Обнови пакет и отдельно
установленные профили `spotty`, `smarty`, `bossy` из одной версии.
Примени процедуру trust выше для изменившихся определений коммуникационных hooks;
сохрани остальные hooks и настройки. Изменение исходников само по себе не означает
обновления runtime-копии; source release выполняется отдельной процедурой.
Если заказано обновление системного промпта, выполни
[его инструкцию](system-prompt.md). Если файлы уже совпадают, повторная запись
не нужна.
После установки совпадающей версии удали только устаревший активный
`agents/properliler.toml`, если он остался от предыдущего пакета Scope Focus;
все остальные профили сохрани.

Сохрани остальные профили, настройки, notebook и данные. При явно выбранном
переносе старого действующего notebook в OS tmp сохрани task key, содержимое
и ссылки на его материалы; не удаляй неизвестные старые notebook или отчёты.
Существующие спецификации из репозитория автоматически не мигрируют и не удаляются.
Проверь обновление по разделу выше. Новые инструкции ToSpec загружаются в новой
задаче; открытая задача может сохранять прежний маршрут. Коммуникационный hook
читает текущий установленный skill при каждом своём событии.
