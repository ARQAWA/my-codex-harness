# Установка

Общий статус и границы установки: [INSTALL_FOR_AGENTS.md](../INSTALL_FOR_AGENTS.md).

## Состав

Для Codex пакет содержит два hook-определения (`SessionStart` и
`UserPromptSubmit`), skill с поручением делегировать при активном Lunatron,
Node.js CLI для извлечения фрагментов (`tools/context.cjs`) и полного захвата
большого вывода (`tools/capture.cjs`) и шесть профилей:
`agents/lunatik.toml`, `agents/luntik.toml`, `agents/lunatron_luna_high.toml`,
`agents/lunatron_sol_low.toml`, `agents/lunatron_sol_medium.toml` и
`agents/lunatron_sol_high.toml`.
Lunatik (`gpt-6-luna/medium`) — свежий полный форк для исполнения блока;
постоянный read-only Luntik (`gpt-6-luna/medium`) отвечает на вопрос к
выбранным большим данным; Luna High (`gpt-6-luna/high`) — сложный блок;
Sol Low, Medium и High (`gpt-6.1-sol`) — блок, которому нужен более сильный
анализ. Main на Luna использует только Luna.

Lunatron ускоряет результат: Main делегирует только большой блок, независимый
от своего следующего шага и выполнимый параллельно, а короткую и
последовательную работу делает сам. Форк наследует историю, поэтому бриф —
несколько строк. Sol реализует блок сам или форкает Luna для большой независимой
части, без Sol→Sol цепочек. Final краткий: статус, результат, изменённые пути,
факты с file:line, проверки, ошибки, неизвестное; родитель использует его без
перепроверки. Завершённых помощников закрывают, когда есть способ; недоступная
роль или форк — блок выполняется напрямую. CLI нужны только для очень больших
выводов; полнота захвата не означает успех команды.

Системный промпт — отдельный компонент поставки, не часть плагина.
После repo-level setup runtime-пакет самодостаточен и не зависит
от документации репозитория.

## Требования

Для Codex нужны CLI с поддержкой плагинов, hooks, app-server, native full-context
fork, Node.js и все шесть профилей помощников.
В `config.toml` активного Codex home установи штатный предел одновременных
дочерних задач не ниже 44, сохранив более высокое существующее значение:

```toml
[agents]
max_concurrent_threads_per_session = 44
```

Если `[agents]` уже есть, добавь или обнови только этот ключ и сохрани прочие
настройки. Зависимостей npm нет. Lunatron поддерживает macOS, Linux и Windows;
в Windows используется только Git Bash, без PowerShell. Lunatron и Tritron не
должны работать одновременно.

В Codex плагин и оба hooks (`SessionStart`, `UserPromptSubmit`) должны быть включены
после установки и обновления.
Сам режим Lunatron по умолчанию выключен для корневой задачи на любой модели.
Контракт выдаётся один раз: на `SessionStart` при активном режиме и на ходу
команды `LNT1`; прочие корневые ходы `UserPromptSubmit` ничего не добавляют,
ходы субагентов получают короткий дочерний контракт. При
`LUNATRON_STATE=ACTIVE` hook указывает Main прочитать bundled skill. `LNT0`
выключает режим: Main останавливает помощников своей задачи, устанавливает
состояние прерванных изменений и закрывает их, когда есть способ; отсутствие
способа не блокирует выключение. Команды слитные, регистр любой, границы —
пробельный символ или начало/конец сообщения. Они распознаются в любом месте
корневого сообщения пользователя, в том числе в блоке кода; последняя команда
побеждает. Остальная просьба в сообщении сохраняется. `LTN`, пробел внутри
команды и `-1` не поддерживаются.
Явный режим хранится в `PLUGIN_DATA/modes/<safe-session-id>.json`; существующие
значения `override: 0` и `override: 1` сохраняются. Автоматического выбора по
модели нет.

## Первая установка

Найди фактическое имя в поле `name` нужного `marketplace.json`. Личный
marketplace из `~/.agents/plugins/marketplace.json` обнаруживается автоматически:
для него `marketplace add` не нужен, даже если его нет в списке. Если другой
источник ещё не подключён, добавь предоставленный локальный путь или Git URL.
Затем установи пакет:

```bash
codex plugin marketplace list --json
codex plugin marketplace add "<источник>"
codex plugin add "lunatron@<marketplace>" --json
```

Настрой `agents.max_concurrent_threads_per_session` в `config.toml` как указано
в разделе «Требования», не уменьшая уже заданный предел.

Подключи все шесть профилей из состава выше из установленного пакета в каталог
`agents` активного Codex home (обычно `~/.codex/agents`). Профили не требуют
отдельного Fast; не включай Fast у Main.

Если системный промпт входит в заказанную установку или обновление, выполни
[его отдельную инструкцию](system-prompt.md) той же ревизии. Иначе его файл
и настройки не меняй.

Настрой доверие к hooks через штатный Codex app-server. Получи определения
через `hooks/list` и запиши нужный trust через `config/batchWrite` в
`hooks.state`: используй точный ключ hook и его `currentHash` как
`trusted_hash`. Меняй только hooks устанавливаемого плагина; уже доверенные
не переписывай. В том же batch для каждого hook Lunatron — `SessionStart`,
`UserPromptSubmit` — запиши `enabled = true` по его точному ключу.
Не обходи trust и не подставляй хеш из прежней версии.

Если в `<active-codex-home>/AGENTS.md` есть прежний точный блок между маркерами
`LUNATRON_GLOBAL_DELEGATION`, удали этот блок и сохрани остальной текст без
изменений. Не создавай блок заново.

## Проверка после установки

В Codex после установки напрямую запусти оба установленных хука с нужными входными
данными на целевой ОС: `SessionStart` и `UserPromptSubmit`. Убедись, что hooks
выполняются без ошибок. На Windows используй Git Bash. Убедись, что прежний блок
`LUNATRON_GLOBAL_DELEGATION` отсутствует. На этом проверка закончена.

Запросы к моделям, пробные задачи, переходы контекста и дополнительные
проверочные процедуры в проверку установки не входят.

## Обновление

### Codex

Обнови пакет через тот же `codex plugin add
"lunatron@<marketplace>" --json`, затем обнови все шесть packaged profiles из
одной версии. Удали из каталога `agents` активного Codex home прежние
`lunatron_luna_xhigh.toml` и `lunatron_sol_xhigh.toml`, только если файл
совпадает с одной из своих packaged версий в истории репозитория:

```bash
for h in $(git log --format=%H -- "plugins/lunatron/agents/<name>.toml"); do
  git show "$h:plugins/lunatron/agents/<name>.toml" 2>/dev/null |
    cmp -s - "<active-codex-home>/agents/<name>.toml" && echo match && break
done
```

Без `match` сохрани файл и сообщи о нём пользователю.
Убедись, что `agents.max_concurrent_threads_per_session` в
`config.toml` не ниже 44; более высокое значение сохрани. Сохрани настройки, данные,
сохранённые результаты, артефакты и остальные плагины.
Профили не требуют отдельного Fast; обычный root режим Main сохраняется.
Через app-server согласуй trust изменённых hook-определений; уже доверенные
не переписывай. Включи оба hook обновлённого Lunatron через их точные
`hooks.state` keys, даже если они были выключены до обновления. Не повторяй bump
source version. Удали прежний точный блок `LUNATRON_GLOBAL_DELEGATION` из
активного Codex home, если он остался, сохранив остальной текст.
Затем выполни раздел проверки для обновлённых частей напрямую.
Полную проверку первой установки без запроса не повторяй.
Новые инструкции загружаются в новой задаче; открытые задачи могут сохранять
прежний контекст.
