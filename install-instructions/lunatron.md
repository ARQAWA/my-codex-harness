# Установка

## Состав

Пакет содержит два hook-определения, контракт Main, Node.js CLI для
подготовки контекста, CLI для полного захвата потенциально большого вывода и
профили `agents/lunatik.toml` и `agents/luntik.toml`.
Lunatik на `gpt-6-luna/medium` исполняет законченный план простого связного блока
в новом полном форке. После приёмки Main закрывает его, если штатный способ
доступен; иначе продолжает без закрытия. Связанные команды,
простая реализация и разрешённые проверки составляют одно поручение до следующего
существенного решения. Lunatik сам исправляет рутинные ошибки и читает свои логи
в границах поручения, сохраняя требования, интерфейсы и полномочия.
Один persistent Luntik отвечает на конкретный смысловой вопрос к уже выбранным
большим данным. Main сам делает обычный поиск и малые чтения и владеет решениями
и приёмкой. Сложный шумный блок вне ролей Luna выполняет одноразовый native
full-context fork типа `default`: для Main Luna/Sol с той же моделью и reasoning,
для Astra — `gpt-6-sol` с тем же reasoning, если инструменты это позволяют.
Если смена модели несовместима с полным форком, сохраняются полный контекст
и унаследованные модель и reasoning Main. Фиксированные профили Luna не меняются.
Отдельный профиль для форка не нужен; другие доступные роли не запрещены.
CLI извлекает фрагменты для ответа Main;
он нужен для требуемых точных цитат и структурного чтения сохранённых
результатов и буквальный поиск. Capture CLI запускает переданную программу без
shell, сохраняет полные stdout и stderr раздельно до host-усечения и возвращает
пути, размеры, exit code, signal и полноту.
Выданная хуком `capture_call` передаёт фактический `PLUGIN_DATA` только процессу
CLI с экранированными путями; глобальное окружение менять не нужно.
Полнота захвата не означает успех команды: отдельно учитываются её exit code
и signal. Новые управляющие состояния и интерфейсы CLI не добавляются.

Системный промпт — отдельный компонент поставки, не часть плагина.
После repo-level setup runtime-пакет самодостаточен и не зависит
от документации репозитория.

## Требования

Нужны Codex CLI с поддержкой плагинов, hooks, app-server, native full-context
fork, Node.js и оба профиля помощников.
Main выбирает вызовы и параметры по текущим описаниям инструментов.
Каждый помощник возвращает final и завершает ход. Закрытие обязательно, когда
есть поддерживаемый способ; без него работа продолжается. Завершение хода
не означает закрытие; неподтверждённое закрытие не объявляется успешным.
Main раскрывает доступные native-инструменты перед первым нужным форком.
Недоступность обязательной возможности требует сообщения о несовместимости,
без скрытой замены исполнением в Main. Дочерний контекст снимает только обязанности
root-оркестратора; профиль, поручение и его границы продолжают действовать.
Не закрепляй для полного форка другую модель или reasoning через профиль
`default`; если общие настройки меняют наследование, Main передаёт оба значения
при запуске форка, если инструмент допускает это с полным контекстом.
Зависимостей npm нет. Поддерживаются macOS, Linux и Windows; в Windows
используется только Git Bash, без PowerShell. Lunatron и Tritron не должны
работать одновременно.

Плагин и оба hooks должны быть включены после установки и обновления.
Сам режим Lunatron по умолчанию выключен на любой модели. Только `LNT1`
включает обязательное делегирование подходящих блоков, включая короткие команды
без параллельной работы. Обычный поиск, малые чтения и приёмка остаются у Main;
чистый вопрос не требует помощника. `LNT0` выключает режим: Main останавливает
работающих помощников, устанавливает состояние прерванных изменений и закрывает
помощников текущей задачи поддерживаемым способом. Отсутствие способа закрытия
не блокирует выключение. Команды слитные, регистр любой, границы —
пробельный символ или начало/конец сообщения. Они распознаются в любом месте
корневого сообщения пользователя, в том числе в блоке кода; последняя команда
побеждает. Остальная просьба в сообщении сохраняется. `LTN`, пробел внутри
команды и `-1` не поддерживаются.
Режим хранится в `PLUGIN_DATA/modes/<safe-session-id>.json`; существующие
значения `override: 0` и `override: 1` сохраняются. Автоматического режима нет.

## Первая установка

Найди фактическое имя в поле `name` нужного `marketplace.json`. Личный
marketplace из `~/.agents/plugins/marketplace.json` обнаруживается автоматически:
для него `marketplace add` не нужен, даже если его нет в списке. Если другой
источник ещё не подключён, добавь предоставленный локальный путь или Git URL.
Затем установи пакет:

```bash
codex plugin marketplace list --json
codex plugin marketplace add "<источник>"
codex plugin add "lunatron@<marketplace>" --json
```

Подключи `agents/lunatik.toml` и `agents/luntik.toml` из установленного пакета
в каталог `agents` активного Codex home (обычно `~/.codex/agents`).
Используй нового lunatik на каждый простой блок и одного persistent luntik. Профили не
требуют отдельного Fast; не включай Fast у Main.

Если системный промпт входит в заказанную установку или обновление, выполни
[его отдельную инструкцию](system-prompt.md) той же ревизии. Иначе его файл
и настройки не меняй.

Настрой доверие к hooks через штатный Codex app-server. Получи определения
через `hooks/list` и запиши нужный trust через `config/batchWrite` в
`hooks.state`: используй точный ключ hook и его `currentHash` как
`trusted_hash`. Меняй только hooks устанавливаемого плагина; уже доверенные
не переписывай. В том же batch для каждого hook Lunatron запиши `enabled = true`
по его точному ключу. Не обходи trust и не подставляй хеш из прежней версии.

## Проверка после установки

После установки запусти каждый установленный хук с нужными входными данными
на целевой ОС. Убедись, что он выполняется без ошибок. На Windows используй
Git Bash. На этом проверка закончена.

Запросы к моделям, пробные задачи, переходы контекста и дополнительные
проверочные процедуры в проверку установки не входят.

## Обновление

Обнови пакет через тот же `codex plugin add
"lunatron@<marketplace>" --json`, затем обнови оба packaged profiles из одной
версии. Сохрани настройки, данные,
сохранённые результаты, артефакты и остальные плагины.
Профили не требуют отдельного Fast; обычный root режим Main сохраняется.
Через app-server согласуй trust изменённых hook-определений; уже доверенные
не переписывай. Включи каждый hook обновлённого Lunatron через его точный
`hooks.state` key, даже если он был выключен до обновления. Не повторяй bump
source version. Затем выполни раздел проверки для обновлённых частей напрямую.
Полную проверку первой установки без запроса не повторяй.
Новые инструкции загружаются в новой задаче; открытые задачи могут
сохранять прежний контекст.
